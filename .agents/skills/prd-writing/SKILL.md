# 写产品 PRD（问答驱动）

> 本 Skill 由 Moonshot 团队 zero 开源，欢迎分享与二次使用。

## 总原则

- **先问后写**。信息不足时必须先向用户提问，不要自己编造数据、目标或竞品结论。
- **证据驱动**。每一个竞品结论都要有实测截图；每一个数据都要有来源。
- **用户微调 = 风格校准**。每次写完主动请用户审阅；用户改过的版本必须重新读取、逐条对比吸收，后续写作立即生效。

## 第一阶段：信息采集（必问）

动笔前向用户确认以下问题（缺什么问什么，一次问完）：

1. **需求主题**：这次的需求是什么？针对哪个产品 / 页面（国内站？海外站？）
2. **竞品 / 参考对象**：对标谁？（如 Claude Platform）有没有指定的参考页面或文档？
3. **数据口径**：现有的漏斗数据是什么？（如曝光→注册→付费的周期数字、转化率，取数时间段）
4. **目标**：目标指标定多少？（基线 → 目标值；要求同时给绝对 pp 提升和相对提升比例）
5. **既有规范文档**：有没有历史埋点文档、多语言清单、设计规范等需要对齐的文档链接？
6. **范围**：是否涉及多语言？是否涉及登录方式差异？是否有既有页面内容需要保留（迁去哪个入口）？

## 第二阶段：竞品调研取证

用 WebBridge 在真实浏览器中走完整路径并截图，证据链必须完整：

- **入口**：从用户描述的入口开始（如 Google 搜索关键词），截搜索结果页，写清「搜索什么 → 点哪个结果进入」。
- **未登录态**：截平台首页（未登录时能看到什么）。
- **登录拦截**：进入平台 / 控制台 / 用户中心时是否强制登录，截登录页。
- **登录流程**：登录方式有哪几种，每个状态各截一张（如扫码 / 手机快捷 / 账号密码）。
- **登录后**：进入平台后的落地页。
- **锚定真实起点页面**：分析「找功能 / 试用功能要几步」时，路径起点必须是用户真实落地的页面（如用户中心 / 控制台落地页），不是想当然的功能页；起点页面拿不准就先问用户或沿线上真实入口走一遍确认。
- **步数对比法**：论证「操作成本高 / 功能难找」时，用「完成同一任务双方各需几步」量化对比（如「试用新模型：我方 4 步（用户中心 → 开发工作台 → 模型下拉 → 选择）vs 竞品首页 0 步曝光」），路径每一步写清页面与动作。
- **参考对象做法先验证再引用**：用户提议「参考 XX 的 Y 做法」时，先实测确认 XX 确实有 Y（例：实测 Claude Dashboard 并无公告区），没有就照实写「XX 无此设计」并改引真正有的参照对象，不凭印象落笔。
- **对比呈现**：竞品与自家产品用**分栏（grid）**左右对照，图注一句话。

操作要点：

- 截图前确认浏览器登录态；需要未登录截图时**先征得用户同意**再退出账号，截完提醒用户重新登录。
- 页面有背景视频 / 动画时，先在页面内 `play()` 让画面渲染出来再截，否则截图是黑块。
- 人机验证（Cloudflare / hCaptcha）无法自动通过，请用户手动点。
- 逐张检查截图：内容是否完整加载、导航栏是否可见，不全就重截。
- 海外站调研时同步确认：当前登录方式（如海外为 Google / 邮箱，无微信扫码）、页面布局（居中或分栏）、语言策略（仅英文或多语言）。
- **Figma 交互稿截图操作**：用 `evaluate` 按文本（如分区名）拿元素实时坐标 → CDP 点击选中 → `Shift+2` 缩放到选区 → `Escape` 取消选中（**不要点空白处，会跳页**）→ `Cmd+\` 隐藏 UI 后截图；嵌套元素首次点击会选中最内层，`Shift+Enter` 上选父级；中键拖拽平移画布；**每次视图缩放后旧坐标全部失效，必须按最新截图重算**（注意 downsampled 截图到 CSS 像素的换算系数，如 1000px 图对应 1512 CSS px 是 ×1.512，方向别搞反）；选区边框在帧外时裁帧内区域即可得到干净图。

## 第三阶段：按结构成文

### 需求背景

结构 = **数据引出问题 → 竞品参照提出假设 → 结论先行 → 最小证据**。

- 第一节：自身数据定义问题（如「当前曝光注册率偏低：新访问 X、注册 Y、转化率 Z%，数据周期」）。
- 第二节：竞品调研作为**假设**（如「参考 XX，可能注册流程过长导致浪费流量」），**结论放在证据之前**；截图只放对论证有直接贡献的，每张配一句话图注。
- **标题与结论要带用户路径成本**：不只写状态（「登录后不可见」），要点出用户因此多走的路径（「要文档站内找到流程很漫长」「试用新模型需 4 步」）。
- 不写调研时间 / 方法 / 过程性描述；不做全景式对比表（截图 + 一句结论已足够）。
- 后续每一节背景同理：问题一句话说清 + 具象化证据（图 / 数据 / 引用文档链接）。

### 需求目的

只写三件事，动作和排期不进来（那是需求详情的位置）：

- **目标一句话**：基线 → 目标，同时给绝对 pp 和相对比例（如 32.71% → 50%，绝对 +17.3pp，相对约 +53%）。
- **收益折算到业务终局**：中间指标 → 付费用户 → LTV（如每周新增注册 6.6 万 → 约 1.32 万付费 → LTV30），假设链条透明。
- **验证口径最朴素**：看什么数、看多久（如「观察 1 个自然周，看上线前后注册转化率变化」）。

### 需求详情

- **页面结构调整**：表格「调整点 | 现状 | 调整后」。写清默认页替换成什么、原内容保留迁到哪个新入口、导航栏增减。
- **新页面原型**：必须出原型图（可写 HTML 线框图后截图），整页布局一张图；局部组件多状态时**单独再出一张状态图**（不要把多状态塞进整页图）。配套拆分表「功能区 | 交互描述 | 文案」：每区域一行，重复内容合并单元格（rowspan/colspan），展示型区域标「仅展示，无交互」，文案列只放页面实际出现的文字。
- **原型布局三规则**：
  1. **保留全部可交互区域**：对标页面上存在的交互区域（如顶部导航在未登录时仍可切换页面、Logo 点击有独立功能），原型中必须保留并在拆分表中说明，不能只画主体卡片。
  2. **区域位置与线上一致**：先核对线上真实布局再画（如协议文案在登录卡片内部底部，不是页面悬浮区）；各区域位置关系不得凭空发明。
  3. **默认态与布局不擅自改**：登录方式默认态、页面布局（海外站登录页参考 Claude 等海外网站用居中布局）与线上保持一致，除非用户明确要求调整。
- **设计稿（Figma）为准**：用户提供交互稿成品后，它取代一切线框图与旧描述——线框原型图全部替换为成品帧截图（帧可加 A～E 区域标注，区域裁切用 PIL 从成品帧裁出并嵌入拆分表「示意图」列，表内插图可行）；**全文清查基于旧交互的描述并清零**（含图注、表格文案、结构调整、多语言、埋点场景说明）；成品若没有组件多状态，先在画板中找状态变体帧（如「另外两种登录样式」分区），找不到才用线上实截并注明组件一致。
- **设计变更级联同步**：设计稿任何修改（笔误修复、导航增删入口、文案调整），必须级联更新：帧截图 → 区域标注 → 区域裁切 → 拆分表 → 结构调整表 → 多语言表 → 埋点场景说明；改完**全文搜索被删关键词**（如被删的导航项名称）确认零残留；表格增删列时逐行校验表头与数据行数一致，防止列错位。
  4. **组件位置与内容频率匹配**：高频操作（创建 Key、充值、测试模型）放首屏；低频内容（平台公告 / 更新日志）不占首屏 C 位，参考更新频率相近的参照对象放置（如 OpenAI Platform 把 Updates 放页面中部右栏，与模型区同屏）。
- **交互来源**：复用线上既有组件时必须注明来源（哪个页面、以线上为准、差异点是什么），并附线上实截图（分栏呈现各状态）。
- **多语言**：单独小节。给语言清单（语言 / 代码 / 站点路径，引用用户提供的清单文档）；翻译覆盖**全部**文案——主副标题、按钮、**输入框占位**、分隔符、协议链接、导航栏，以英文为源语言，表格按「语言 × 文案项」全量给出。先调研参考对象的语言策略（仅英文 / 多语言）。

### 埋点设计（独立章节，放在需求详情之后）

- 先读用户的既有埋点规范文档，**事件命名、属性前缀、表格格式全部对齐**，不自创规范。
- 曝光 + 点击全覆盖：先枚举线上页面的所有模块和所有可点元素（导航 / CTA / 卡片 / Footer 链接），每个模块有曝光事件，每个可点元素有点击事件。
- 三张表：公共属性（属性名 / 说明 / 是否必需 / 取值示例）、事件总览（模块 / 事件名 / 场景说明 / 关键属性）、事件属性说明。
- 验收口径（每个模块有曝光、每个可点元素有点击、漏斗每步转化率可查）。

## 写作规范（每条都是用户调教过的，必须遵守）

- **简洁**：删形容词、删铺垫、删重复；句子只留主干，数字和事实说话；无歧义。
- **总结性内容前置**：结论、验收口径、规范来源放在小节最前面（说明之后、细节之前）。
- **引用块（blockquote）**：图注、交互来源、备注、验收口径、规范来源等辅助说明一律用引用块；同类内容合并成一个引用块。
- **表格替代表述**：对比、调整点、参数说明优先用表格；重复内容合并单元格，不重复写。
- **分栏对比**：双方截图证据用 grid 左右分栏，不用整宽竖排堆图。
- **同类项对比**：整页对整页、导航对导航、卡片对卡片；图放完整页面，不拿局部裁剪图去对别人的整页；同一页面支撑不同论点时可复用同一张整页截图，图注按各自论点写。
- **图注编号连续**（图 1、图 2……），改图后检查编号不重不漏。
- 写操作后必须重新 fetch 验证（结构、图片、编号、位置是否符合预期）；替换 block 后旧 ID 失效，用最新 ID。

## 交付与校准

1. 完成初稿后，明确告诉用户写了哪些部分、证据是什么，请其审阅。
2. 用户微调后，重新读取改后版本，逐条列出「我的写法 vs 用户的写法」差异，吸收为后续准则，再继续工作。
